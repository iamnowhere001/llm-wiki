# Tim Berners-Lee 与万维网的单向链接妥协

> 万维网的创造者。他在链接拓扑上做了一个**被论证过的工程取舍**：放弃双向链接，换取万维网的普遍采用。他本人清楚双向在信息层面更优（「实际上是免费增加了信息」），但治理成本过高。

- **类型**：人物
- **别名**：TimBL、Sir Tim Berners-Lee
- **外部链接**：https://en.wikipedia.org/wiki/Tim_Berners-Lee
- **一手材料**：[[2026-09-18-berners-lee-link-topology]]

## 是什么

万维网的发明者。在本知识库中，他的意义**不在于「发明了网页」**，而在于他留下的那份设计笔记，让我们看到 **「单向链接」是一个经过权衡的决定，而不是疏忽**。

本库对这个角色的处理有个明确立场：**不要把他写成「选择了较差方案的人」。** 他是在「双向 + 无法普及」与「单向 + 可以普及」之间选了后者，且明说了理由。

## 关键事实

| 时间 | 事实 | 来源 |
|---|---|---|
| c.1999 | 撰写设计笔记，逐条权衡双向链接的利弊，并提出「数据模型单向 + 自动生成反向链接」的折中方案 | [[2026-09-18-berners-lee-link-topology]] |
| — | 万维网最终采用单向链接，原因是治理成本（过滤、审核、权限）过高，而创造者的目标是普遍采用 | [[2026-09-18-appleton-bidirectional-links]] |

## 他的取舍

一手材料 [[2026-09-18-berners-lee-link-topology]] 里，正反两面都被写下来了：

**支持双向**：「双向链接让系统可以推导出反向关系 —— 若 A 包含 B，则 B 是 A 的一部分。**这实际上是免费增加了信息。**」当系统的关键参数是「建立一条链接要花多久」时，这一点尤其重要。此外，双向链接对数据管理有用 —— 文档被销毁或移动时能预知悬空链接。

**反对强制**：「强制双向的一个缺点是**它会约束超文本的作者** —— 他可能想约束读者。」以及一个当时无解的问题：如何对一个受保护的数据库建立双向链接。

**折中方案**：「**数据模型里链接是单向的，但当任何链接被建立时，创建一个反向链接**，只要这不会侵犯保护机制。」替代路径是用后台进程在单向网络上收集反向链接。

[[2026-09-18-appleton-bidirectional-links]] 补上了这份笔记没写明的部分 —— **为什么最终没采用折中方案**：若每个指向你的站点都可见而你又无法控制谁可以链接你，「恶意引用的后果」不难想象；过滤、审核、权限的设计细节「变得相当复杂」。考虑到目标是普遍采用，用更简单的单向链接实现万维网是正确的事。

## 在本知识库中的角色

他是历史链条上 **1965 → 1989/1999** 这一步的承担者，与 [[ted-nelson]] 构成一组关键对照：

| | [[ted-nelson]] / Xanadu | [[tim-berners-lee]] / 万维网 |
|---|---|---|
| 链接方向 | 双向，且可追溯引用与改写 | 单向 |
| 目标 | 完整的双向信息网络 | 普遍采用 |
| 结果 | 未实现 | 成为全球基础设施 |
| 代价 | — | 失去了「反向关系」这一免费信息 |

**对 [[llm-wiki-pattern]] 的意义**：他的折中方案 ——「单向数据模型 + 自动生成反向链接」—— 在 1999 年难以实施（需要全网协作或可信的后台进程）。**在 LLM 出现后它变得可行**：让 LLM 维护私有知识库里的 `related` 字段与反向链接，等价于他描述的「后台进程收集反向链接」，只是作用域从全网缩小到单库。见 [[bidirectional-links]]。
