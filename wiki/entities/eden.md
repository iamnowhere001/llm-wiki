## 是什么

按 [[dan-koe]] 的自述，Eden 由他此前做的 Kortex 演变而来。定位是「创作者找趋势内容」+「创意工作者从任何地方捕获想法」的组合。核心能力描述包括：

| 能力 | 描述 | 来源性质 |
|---|---|---|
| 捕获 | 保存任意链接或想法到一个大库 | 厂商自述 |
| 自动整理 | 自动打标签、分类、嵌入 | 厂商自述 |
| 转录 | 保存 Substack / YouTube 链接时自动转录，可高亮 | 厂商自述 |
| Kindle 集成 | 拉取历史高亮 | 厂商自述 |
| 意义检索 | 按**意义**而非关键词检索（「什么在附近」而非「什么相关」） | 厂商自述 |
| 选题研究 | outlier search —— 找本领域表现最好的社交帖子 | 厂商自述 |
| MCP | 提供 MCP 接口，可让 Claude 访问该知识库 | 厂商自述 |

## 在本知识库中的角色

它是**嵌入检索路线的商业形态代表**。作者用一句对比概括了它与关键词检索的差别：

> Obsidian 能给你看「什么是相关的」，Eden 能给你看「什么是邻近的」—— 因为每个想法被嵌入成约 1500 个数字，像 GPS 坐标。即使两个想法一个词都不共享，也能被找到。

这与 [[qmd]] 的技术取向一致（混合 BM25 + 向量），但落点相反：qmd 是**本地自建工具**，Eden 是**托管服务**。作者还列了自己维护向量库的隐性成本 —— 索引脚本、笔记变更后重新嵌入、文件重命名后同步、缓存以避免重复付费。

这个对比补进了 [[index-and-log]] 讨论的「索引文件何时失效」问题：判断依据不只是页面数，还包括**是否需要发现非关键词的邻近连接**。

## 待验证的部分

**本页的几乎所有能力描述都是厂商自述。** 作者是 Eden 的运营者，文章本身是推广材料。因此：

- 无法确认「按意义检索」的实际效果与普通嵌入检索的差别
- 无法确认自动标签分类的准确率
- 无法确认 MCP 接口的实际能力边界
- 「最好的市场工具」这类表述属于营销语言，不构成事实

[[dan-koe]] 在同一篇文章里批评「Claude skills 是一阵会退去的风潮」，同时推广自己的产品 —— 这个张力值得留意：**批评工具崇拜的立场，与售卖工具的行为并不完全一致。**
