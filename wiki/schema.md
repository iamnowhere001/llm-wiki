## 1. 页面规范

### 1.1 Frontmatter（每页必需）

```yaml
---
title: 页面标题
type: concept            # source | entity | concept | analysis | project | meta
slug: llm-wiki-pattern   # 全库唯一，与文件名一致（不含 .md）
tags: [知识管理, 模式, LLM]
created: 2026-09-18
updated: 2026-09-18
sources: [2026-09-18-karpathy-llm-wiki]   # 支撑本页的 raw 素材 slug
related: [rag-vs-wiki, ingest-query-lint] # 相关页面 slug
evidence_tier: single    # single | crossed | primary —— 见 1.2
confidence: high         # high | medium | low —— 证据充分度（主观判断）
status: active           # active | draft | stale | deprecated
---
```

**`slug` 必须与文件名一致**，且全库唯一。工具链靠它解析链接。

`meta` 与 `project` 页不需要 `sources` / `evidence_tier`：前者是系统文件，后者的来源是「我要做什么」而非某份素材（`lint` 已豁免）。

### 1.2 `evidence_tier`：这页的结论站得多稳

`confidence` 是 LLM 的**主观**判断，会随阅读而变，机器校验不了。
`evidence_tier` 是**可计算的事实** —— 由 `sources` 列出的素材数量与类型推导，`lint` 会校验它与事实是否一致。
**两者是两个维度，不要互相替代**：一页可以有 8 份素材支撑（`crossed`）但仍然 `confidence: low`（因为那 8 份全是转述）。

| 取值 | 判据 | 意味着 |
|---|---|---|
| `single` | 恰好 1 份支撑素材 | **孤证**。可读可引用，但引用时必须带着「只有一份来源」这个前提 |
| `crossed` | ≥2 份支撑素材，且不含一手文献 | 交叉了 —— 但**可能只是同源转述**（见下） |
| `primary` | ≥1 份 `kind: paper` 的素材支撑 | 有可独立核验的一手文献 |

> [!warning] 「名义交叉，实质同源」是本库最大的陷阱
> 多份素材不等于多个独立佐证 —— 本库实测有 **70 份素材同属一个来源族**（同一套得到课程的讲稿、问答与整理笔记）。
> 一个概念页列出了 5 份支撑素材，可能只是同一个人的转述被拆成了 5 份。
> `lint` 会额外报出「有 ≥2 份支撑但全部来自同一来源族」的页面 —— **那些页面不能当作已交叉验证**。
>
> **归并失败时默认「各自独立」，不并族。** 判不了就别判 —— 把真交叉误判成同源（冤枉一个其实站得住的页面）比漏报同源的代价更大。

**写入方式**：`tools/seed_evidence_tier.py`（幂等，可反复跑）。手工新建页面时按上表填；填错了 `lint` 会报「evidence_tier 与支撑素材不符」。

> [!note] 2026-09-19 裁定：`primary` 的判据**不扩**到 `book` / `essay` / `design-note`
> **起因**：本库入库第一份完整专著（[[2026-09-19-art-of-impossible-book-en]]，`kind: book`）后发现它**永远触发不了 `primary`**。
> 同类情况库里已有 ≥4 份：Bush 1945（`essay`）、Berners-Lee 1999（`design-note`）、Luhmann 1981（`essay`）、Kotler 2021（`book`）。
> **北洛裁定：不扩。**（理由：一本自助书也是 `book` —— 把 `book` 一律认作 `primary` 会让这个字段失去分辨力。）
>
> **含义必须读懂，否则会误用这个字段：**
> - **`primary` 不是「证据强度排名」，是「有没有期刊论文级的一手材料」这一个事实。**
> - 因此**一手专著会停在 `crossed`**。这不是低估 —— 是**字段管不了这件事**。它管来源类型，不管可信度。
> - **补救不在字段里，在正文里**：这类素材的 `sources/` 页与它支撑的知识页，**必须用文字显式写明「本页有一手专著 / 作者一手文本支撑」** ——
>   `lint` 与 `evidence_tier` **都不会替你说这句话**，漏写就会被后来的读者按「二手转述」对待。
> - **不得为了让层级好看而把这类素材标成 `paper`** —— 那是虚升素材性质，与本库做法相反。
> - **`primary` 页也未必比 `crossed` 页可信**：一页可以是 `primary` 但仍 `confidence: low`（论文本身质量差）。**两个维度始终是独立的。**

> [!note] 2026-09-19 裁定：「自写 `> [!warning]`」的边界（**收窄**，并首次落档）
> **原规则**（此前只存在于 `.workbuddy-ai/memory/MEMORY.md`，本文件与 [[decisions]] 均无）：
> 「`> [!warning]` 归脚本独占，自写的观察一律用 `> [!note]`。」
> **实测不符**：全库有 **200 处自写 `> [!warning]`**（python 逐页扫描，非 `grep`）—— **规则比现状宽 200 倍**。
> **北洛裁定（2026-09-19）：收窄规则，不回填那 200 页。** 理由：真事故只有一种形态，规则应当只禁止那一种。
>
> | 情形 | 判 |
> |---|---|
> | 自写 `> [!warning]`，**与脚本块同页同题** | **禁止** —— 脚本撤不掉它，还会再插一个标准块 → 同页两个警示块 |
> | 自写 `> [!warning]`，该页无同题脚本块 | **允许** —— 那 200 处现状全部属此类，不动 |
>
> **脚本独占的两种块**（`seed_evidence_tier.py` 负责插入与撤除）：`> [!warning] 孤证 —— …`、`> [!warning] 名义交叉，实质同源 …`。
> **自查方法**：写完 warning 后跑一次 `python3 tools/seed_evidence_tier.py --write`；若该页出现**两个 warning**，就是踩了这条 —— 把自己的那个改成 `> [!note]`。
> **已发生的实例**：`prospect-theory`（2026-09-19）、`birgitta-bockeler`（2026-09-19）。
> **为什么仍然要写进本文件**：这条规则此前只活在项目记忆里，而项目记忆随会话注入、不随库分发 —— **读者读 `schema.md` 时看不到它，就会再踩一次。**

### 1.3 页面类型

| type | 目录 | 一页是什么 | 何时创建 |
|---|---|---|---|
| `project` | `projects/` | **我在做的一件事**：目标、当前缺口、消耗的知识、产出 | 人类提出一个要推进的目标 |
| `source` | `sources/` | 一份素材的结构化摘要 | 每次 ingest |
| `entity` | `entities/` | 一个具体的人 / 组织 / 工具 / 产品 | 素材中反复出现的具名对象 |
| `concept` | `concepts/` | 一个抽象的理论 / 方法 / 模式 / 术语 | 素材中反复出现的抽象概念 |
| `analysis` | `analyses/` | 一次对比 / 综述 / 回答归档 | 有价值的问题答案、跨页综合 |
| `meta` | `wiki/` 根 | index / log / overview / conventions / schema / decisions | 系统文件 |

**判定规则**：能被指着一张照片说「这是它」的 → entity；只能被描述、不能被拍照的 → concept。

**创建阈值**：一个名字在 ≥2 份素材中出现，或者在一份素材里是核心论点 → 独立成页。只出现一次的次要名词，先在正文里提一句，等它再次出现再建页。

### 1.4 正文结构

每个页面遵循「**先结论，后细节**」：

```markdown
# 标题

> 一句话定义（TL;DR）。读者只看这一行也能知道这页在讲什么。

## 要点
- 3-6 条要点

## 正文
展开论述。用 [[wikilink]] 建立交叉引用。

## 与其他页面的关系
- 区别于 [[x]]：...
- 是 [[y]] 的前置：...

## 待办 / 开放问题
- [ ] 需要补充的资料

## 来源
- [[2026-09-18-karpathy-llm-wiki]]
```

### 1.5 链接语法

- 页内链接：`[[slug]]` 或 `[[slug|显示文本]]`
- **只链接已存在的页面。** 如果 `[[x]]` 指向不存在的页，lint 会报 broken link —— 要么建页，要么去掉链接。
- 每页至少 **1 条出链**（除 `sources/` 外）和 **1 条入链**。孤立页会被 lint 标出。

### 1.6 项目页（入口层）

项目页回答的不是「这是什么」，而是**「我在做什么、因此什么重要」**。它是本库的**过滤器生成器**，依据来自 [[cybernetic-learning]] 的链条：

```
目标 → 误差信号 → 过滤器 → 相关性 → 留存
```

没有目标，就没有误差信号；没有误差信号，大脑不会标记什么重要。**项目页就是把「目标」和「误差信号」显式写下来的地方。**

#### frontmatter

```yaml
---
title: 项目名
type: project
slug: project-slug
tags: []
created: 2026-09-18
updated: 2026-09-18
goal: 一句话目标，要能被判断「完成没有」   # 项目页特有，必填
stage: planning                          # 项目页特有
started: 2026-09-18
sources: []      # 项目通常留空 —— 它的来源是意图，不是素材
related: []
confidence: high
status: active
---
```

**`stage` 与 `status` 是两个维度，不要混用：**

| 字段 | 回答的问题 | 取值 |
|---|---|---|
| `status` | 这**页**还新鲜吗 | `active` / `draft` / `stale` / `deprecated` |
| `stage` | 这**事**做到哪了 | `planning` / `active` / `paused` / `shipped` / `abandoned` |

#### `goal` 必须可验收

反例：「学习 Rust」「研究知识管理」。
正例：「用 Rust 写一个能跑的命令行工具并发布到 GitHub」「把本库的历史线补到 1990 年代之前」。

判据：**看到 goal 能回答「做完了没有」**。不能验收的目标产生不了误差信号，等于没写。

#### 正文结构与作用

| 小节 | 作用 | 对应控制论要素 |
|---|---|---|
| 目标（可验收） | 参考信号 | 目标 |
| **当前缺口** | **误差信号** —— 全页最重要的一节 | 误差信号 |
| 知识 | 本项目消耗哪些页面 | 相关性 |
| 产出 | 外向回路 —— 知识流出到哪里 | 留存 / 复用 |
| 决策记录 | 项目里做过的判断（AI 拿不到的部分） | — |
| 不做什么 | 反范围，避免蔓延 | — |

**「当前缺口」是项目页存在的核心理由。** 它必须写成表格：`缺口 / 卡在哪 / 需要什么素材`。这张表直接决定下一步找什么素材。

表格保持三列。需要标优先级时，在「缺口」列内用 `**【阻塞】**` 前缀 —— 它表示这一条直接挡住 `goal` 的验收条件，必须先解；未标的是可选或可延后的。

**缺口表有两类条目，不要混（2026-09-19 北洛裁定新增第二类）：**

| 类 | 形态 | 含义 |
|---|---|---|
| **文献缺口**（默认，绝大多数） | 「知道缺什么，卡在哪，需要什么素材」 | **有来源提示过这里有洞** |
| **未知缺口** | 「本库不知道这里缺什么，因为**没有任何来源提示过**」 | **洞本身是不可见的** |

**「未知缺口」不是循环论证。** 它与 §4.1「说『库里没有 X』之前必须先检索并写明检索了哪几段」**同型** ——
**都是把「不知道」变成一个需要举证的状态**，只是作用域从「一句话」扩大到「整个素材池」。

**判据**：一个项目的缺口表里，如果**全部**条目都是文献缺口，那大概率是没做过偏差分析 ——
因为真实情况总有一部分是未知的。

**「未知缺口」的写法**：仍用三列，但第三列**不指定具体素材**，而是写**什么机制能让这个洞变得可见**
（例如「需要另一条独立渠道」而不是「需要某份文献」）。**判据：能说出「这个问题是 X 渠道带来的，而现有渠道从未提过」，这条缺口才算有了观测手段。**

首个实例：[[llm-wiki-research]] 的「素材渠道筛选掉了什么」（实测 `raw/` 99 份中 82 份来自同一域名）。

> [!warning] 「未知缺口」不能当通行证 —— 它不满足「填得上缺口」的检验
> `AGENTS.md` §3 第 7 条要求「收录前先读缺口表，**填不上任何缺口的素材现在还不该收**」。
> **一条「未知缺口」不构成「填得上」** —— 否则任何素材都能声称自己在填未知缺口，这条前置检查立刻失效。
> **判据**：声称在填「未知缺口」时，必须同时说明**这份素材如何把那个洞变得可见**
> （例如它提供了本库从未有过的材料类型）。**说不出这一点，就是没对上任何缺口。**
> **「未知缺口」的用途是「说明为什么收不到」，不是「放行任意素材」。**

#### 生命周期

- 项目 `shipped` 后**不删除**。它的「决策记录」是后续项目最值钱的参照。
- 项目 `abandoned` 时，在「决策记录」里写清**为什么放弃** —— 这比成功记录更稀缺。
- 项目长期 `paused` 且无产出，考虑降级为 `analyses/` 里的一页，或标 `stage: abandoned`。

**终点判据：缺口表清空即 `shipped`**（不是「没有【阻塞】条目」）。决定不做的缺口**移入「不做什么」**，否则表永远清不空。清空之后来的新素材按三条分流：

| 情形 | 处理 |
|---|---|
| 新素材填的是**现有缺口** | **不构成新项目** —— 正常 ingest，项目仍是 `active` |
| 缺口表**已清空**（项目已 shipped）后，新素材开的是**新缺口** | **另开一个项目**，原项目保持 `shipped`，**不复活** |
| shipped 后，新素材**推翻了原项目的结论** | **不是新项目，是原项目复活** —— `stage: shipped → active`，并在决策记录里写明是哪条结论被推翻 |

> [!warning] 「另开一个」必须防的退化
> **另开项目 ≠ 从零开始。** 后继项目**必须显式继承前任**：在「决策记录」里引用前任 slug、在缺口表里标明哪些缺口是继承的、把前任被否决的方案与伦理风险标记**重申一次**。
> 否则前面那个项目的全部工作（缺口判定、被否决的方案、风险标记）都会失效，团队重复劳动、重复踩坑。
> 完整理由见 [[decisions]]。

### 1.7 标签规范（2026-09-20 **二次**裁定）

`tags` 是**导航字段**，不是关键词堆。它只有一个用途：**让同一主题的页面在侧栏、索引与标签面板里聚到一起**。

**判据 —— 把标签念成一句话：**

| 念成 | 判 | 例 |
|---|---|---|
| 「这页讲 **＿**」 | **保留**（主题） | `认知科学` `决策` `心流` `鲍莫尔成本病` |
| 「这页属于 **＿**」 | **保留**（系列归属） | `现代思维工具` `成长战略` `世界观` `演化者` |
| 「这页出自 **＿** ／ 是 **＿** 说的」 | **保留**（署名） | `万维钢` `塔勒布` `孔子` `Thoughtworks` `得到课程` |
| 「**＿** 是谁」 | **保留**（角色） | `人物` `研究者` `经济学家` |
| 「这页 **是** ＿」 | **移除** | `素材` `纯讲稿` `一手文献` `AI生成` `模块八` `待裁定` |

最后一行是全部规则：**`tags` 里不出现「关于这一页自己的属性」。**
素材形态、核查状态、生成方式、抓取与组织元数据 —— 四类都属此列，因为它们描述的是**这一页的处境**，
不是**这一页的内容**。

> [!note] 2026-09-20 二次裁定：第一轮的「剥离署名」被推翻
> **第一轮（同日早些时候）**：署名 / 时代大概念 / 角色三类全库剥离，813 → 299 个标签。
> **北洛推翻**，原话：「署名、概念、角色等标签加回，流程 / 证据元数据类移除 ——
> 前面我理解错了，只是觉得**万维钢出现的频率实在太高了**，他是个专栏作家，是解读书籍与新科学理解的，
> **很多理论观点并非出自他**」。
>
> **两轮的差别不在「万维钢该不该留」，在「用什么判据评价一个标签」**：
> - 第一轮把它当成**覆盖 44% 的坏标签**（判据：区分度 —— 一个标签盖住 179 页，切不开任何东西）。
> - 第二轮的判据是**归属**：`万维钢` 是署名，它回答「这页出自谁」，不回答「这页讲什么」。
>   **一个字段不因高频而失效；拿错了维度去评价它，才会得出「该删」的结论。**
>
> **但北洛的顾虑是真的，而且两轮裁定都没有解决它**：
> `万维钢` 是**转述者**，不是**提出者**。库里大量概念的提出者是霍林、塔勒布、古德哈特……
> 署名标签只记「这页出自谁」，**不区分「谁提出」与「谁转述」** ——
> 这正是本库已登记的毛病「**署名恰是中文转述省掉的那项**」。
> **要表达「谁提出」，靠实体页与正文，不靠标签。** 这一点已写进下面的已知代价。

**移除集只有一份**：`tools/tags_vocab.py` 的 `REMOVE`（分 `FLOW` / `GENERATION` / `CAPTURE` / `STATUS` 四组）。
`lint` 报出任何**落在移除集内**的标签，检查名 `标签属于移除集`。

**本规则不再有频次门槛。** 第一轮曾用「≥2 页才准入」把词表压到 299 个；**二次裁定后该门槛已废** ——
它会把只出现在一页上的**署名**与**主题**一并删掉，而「只出现一次」恰恰是署名与专题词的常态。
代价是词表重新变长（**619 个**，2026-09-20 实测），**这个代价是被接受的**。

**顺序**：顶栏按 **系列 → 署名 → 主题** 排，组内按全库频次降序。由粗到细：先定位归属，再看内容。

> [!note] 2026-09-20 裁定：侧栏二级分组已删除
> **此前的登记**（原文见 [[decisions]]）：侧栏一级按 `type`、**二级按 tag** 切，切出来的前两层是
> `万维钢` → `得到课程`，不回答「这页讲什么」；当时因「只改内容，不动渲染」而**只登记不修**。

> 而是**把二级分组整层删除**。

> - 只有 **6 个一级组**（按 `type`），组头 sticky、可折叠，展开状态写 `localStorage`。
> - **组内平铺，没有第二层**；页数 ≥ 20 的组（`source` / `entity` / `concept`）挂**组内筛选框**，

## 2. 收录

人类把素材丢进 `raw/`，然后说「收录」。

> [!note] 曾经的前置条件已废止
> 原有一条「第 −1 步：人类先问（HFQ）」，要求人类在 LLM 读素材前亲笔写下收录理由与自己的问题。
> **已于 2026-09-18 移除** —— 现在 ingest **没有任何人类前置条件**，人给链接，LLM 即可开工。
> 墓碑与连带影响见 [[decisions]]。

**第 0 步：读 `wiki/projects/`。** 判断这份素材服务于哪个项目的哪个缺口。
- 能对上 → 在 `sources/` 页里写明「服务于 `[[项目slug]]` 的哪个缺口」，并在项目页的「知识」一节加回链。
- 对不上任何缺口 → **先向人类指出**：「这份素材填不上任何当前缺口，确定要收吗？」

这不是形式主义 —— 它是 [[cybernetic-learning]] 的过滤器在流程上的落地。
**若本库还没有任何项目页，先提醒人类建一个**（`lint` 会在知识页 ≥10 时提示）。

然后按顺序执行：

1. **抓取**：质量要求见 §3。落盘后校验一次链接是否还在。
2. **读**：完整读一遍素材，含 frontmatter。如果素材引用图片，先读文本，再单独查看关键图片。
3. **对齐**：向人类汇报 3-5 条关键要点，以及它与现有 wiki 的关系（新增？印证？**矛盾**？）。若素材与已有页面冲突，**明确指出，不要悄悄覆盖**。
4. **核查** —— **L0 事实核查每次收录都做；L1 全文校准命中触发条件才做。**（2026-09-19 北洛裁定，完整规则见 §3.8）
   - **L0（必做）**：对素材里**带数字、带引号、带署名**的断言逐条核出处。核的是「**这个片段里有没有这个断言**」—— 通常一段就够，**不必把原文收进 `raw/`**。
   - **链接可信时的正确动作**：读链接指向的那一段、确认它**说了那句话** —— 而不是确认链接**能打开**。后者正是 §3.6「伪引注」最常伪装的形式。
   - **L1（条件性）**：触发条件三条 —— 原文已在库 / 下游引用 ≥3 处 / 已出现具体怀疑。**命中任一才做全文对照**，都不命中就只做 L0。
   - **核不到就如实写「未找到」或（未验证），不要留空** —— 「核过而没有」本身就是信息。
5. **（条件性）反方检索** —— **AI 生成占比 > 60% 的素材，收录时必须跑一次反方检索。**（2026-09-19 北洛裁定）
   - **口径**：AI 占比按 §3.7 的分层表算，取**占正文行数的百分比**（本库既有惯例）。分层在「读」这一步完成，占比在写摘要页时落笔 —— **不要等写完摘要页才回头补检索**。
   - **为什么**：这类素材最可能缺的正是反方 —— AI 倾向于给共识不给争议（见 [[source-pool-bias]] 第三节第 ③ 条）。
   - **做什么**：检索对这份素材**核心主张**的批评 / 复现失败 / 元分析，结果写进摘要页的「反方与失败条件」一节。**若检索不到反方，如实写「未找到」，不要留空** —— 「检索过而没有」本身就是信息。
   - **成本**：一次检索。收益：省掉「基于它写了三页之后才发现」的返工（先例：[[andrew-saxe]]，收录当天就拿到反方）。
   - **不溯及既往**：本条只管**新收录**。已入库的高占比素材**不补做** —— 但下一轮 **L1 全文校准**时顺带处理（触发条件见 §3.8）。
6. **写摘要页**：`wiki/sources/<slug>.md`，按模板。slug 取 `YYYY-MM-DD-短标题`。
7. **拆实体 / 概念页**：按 §1.3 的阈值，新建或更新 `entities/`、`concepts/`。
8. **回填**：更新所有被影响的已有页面 —— 补充事实、修订结论、标注矛盾。
   **一份素材通常触及 10-15 个页面，只写摘要页是失败的做法。**
9. **更新索引**：在 `wiki/index.md` 对应分类下加入新页与一行摘要。
10. **写日志**：`python3 tools/wiki.py log ingest "素材标题"`。
11. **自查**：`python3 tools/wiki.py lint`，确保无 broken link。
12. **（条件性）构建站点**：只在里程碑时 —— 判据见 §2.1。

### 2.1 构建时机 —— 只在里程碑时

`site/index.html` 是**构建产物**（`python3 tools/wiki.py build`）：它把 `wiki/` 下全部页面连正文内联成一个单文件，供浏览与分享。**它不是文档，是视图** —— 因此**不与 `index.md` / `log.md` 同级、不需要每次更新**。

**判据（满足任意一条即是）：**

| # | 触发条件 | 为什么算里程碑 |
|---|---|---|
| 1 | **新增一条主线** | 「这个库在讲什么」变了 |
| 2 | **新增或关闭一个项目** | 入口层变了 |
| 3 | **页面总数变化超过 10** | 站点体积与导航结构有可见变化 |
| 4 | **一次大 ingest 收尾** —— 整系列收录、多份素材同批、或一份素材派生 ≥5 个新页 | 单次改动量大，零散重建不划算 |
| 5 | 人类明确要求 | —— |

**不命中的改动（单页回填、修笔误、补一条待办、调整 `related`）一律不构建。**

> [!warning] 没有任何机制会发现站点落后
> `lint` 只管 `wiki/` 下的 Markdown；`index` 只管 `wiki/index.md`。**`site/` 不在任何检查的覆盖范围内。**
> 因此本条的落地方式不是「记得构建」，而是「**照上表逐条判断**」：一次 ingest 结束后回看五条 —— 有命中就构建，**都不命中就明确地不构建**。
> **「明确地不构建」与「忘了构建」在结果上一样，在过程上不同** —— 前者可审计，后者是事故。

**构建后顺手做一件事**：在 `wiki/log.md` 记一条 `edit`，写明**上一次构建的时间**与**本次跨越了几次改动**（例：「此前停在 18:11，之后发生三次 ingest」）。**这条记录是日后判断「站点还可不可信」的唯一依据** —— 没有它，站点是否新鲜就只能靠猜。

> [!note] 与「更新索引」的区别
> `index.md` 是**知识库的组成部分**（查询的第一站），**必须每次更新**；
> `site/index.html` 是**从知识库导出的一份快照**，**允许滞后**。
> 把两者混为一谈，会让「必须做的」和「可以攒着做的」共用同一条规则 —— 那才是常驻成本失控的来路。

## 3. 抓取质量与证据问题

### 3.1 质量优先于速度

网页正文抓取会丢行内链接、把 `→` 转成 `->`、丢表格分隔符。**只要目标提供结构化端点，就用它**：

- GitHub 仓库 → `api.github.com/repos/<owner>/<repo>`（元数据）+ `/readme`（base64 正文）
- Gist → `gist.githubusercontent.com/<user>/<id>/raw`（正文原文）
- X / Twitter → `cdn.syndication.twimg.com/tweet-result?id=<id>&token=a`（元数据 + 正文预览）
- 飞书云文档 → `lark-cli docs +fetch --doc-format markdown --as user`
- 静态文档站 → 直接取 `.md` 源文件而非渲染后的 HTML

落盘后**校验一次**：正文里应该有链接的地方是否还有链接。捕获缺陷在收录时发现成本最低。

**若只能用 AI 中介的抓取工具（如渲染页提取），必须交叉验证** —— 用独立元数据源比对（例如 syndication 端点返回的 `preview_text` 与正文开头是否逐字一致），并在 `capture_quality` / `capture_note` 中如实记录可信度与已知缺失（如图片未能下载）。

### 3.2 抓取元数据例外（清理历史遗留专用）

**这不是常态化的可写权限。** `raw/` 不可变是铁律，本条只用于清理**历史遗留的错误元数据**。

**准入条件（必须全部满足）：**

1. **只限 frontmatter，正文一字不可改。** 正文抓取有误 → 走 `-r2` 重抓流程。
2. **只限「本库自产的描述性字段」** —— 白名单：
   `capture_note` / `capture_quality` / `capture_method` / `clipped` / 抓取标识（`revision_id` 等）/ `assets`。
   **黑名单（绝不可改）**：`title` / `author` / `url` / `published` / `kind` —— 这些是**素材自身的属性**或**指向素材的地址**，改它们等于篡改来源标识。
3. **必须由人类裁定。LLM 不得自行修改。** LLM 只能提出更正请求并附证据（行号 + 该行的实际内容），由人类说「改」。
4. **不得覆盖，只能追加。** 旧值留在原地，新值以显式标注追加。**「可更正」≠「可覆盖」** —— 允许覆盖就等于允许消灭证据。
5. **优先「移除」而不是「改正」。** 若某字段里的数据本身就是错的（典型是行区间），**把它整段删掉、改为指向 `sources/` 页的指针** —— 新数字同样可能错，而**指针不会**。这是首选处置方式。
6. **改动必须同时做三件事**，缺一不可：
   - `wiki/log.md` 记一条；
   - 对应 `sources/` 页写明「raw 元数据于 X 日更正，原值 Y，依据 Z」；
   - **扫描并更正所有下游引用** —— 否则只是把问题搬了个地方。
7. **一次只改一个字段**，改完立即 `lint`。
8. **尽量用等行数替换。** 改 frontmatter 会改变文件行数，从而使所有行区间失效。无法避免时**必须重新测量全部区间并按第 6 条同步下游**，并把新的基准版本（行数）写进相关 `sources/` 页。

### 3.3 行区间必须写明坐标系

**规则**：任何行区间断言都必须写明坐标系，默认用**文件绝对行号**（`wc -l` 的坐标系）。
写「行 165–175」之前，回文件 `sed -n '165,175p'` 看一眼。**凭记忆沿用行号是本库已犯过三次的错。**

**怎么识别旧数据用的是哪个坐标系**：若 `capture_method` 里记的「正文 N 行」**小于** `wc -l` 的实际行数，那 N 就是**内容相对**的行数，差值即 frontmatter 长度 —— 该文件里的全部区间都偏了这么多。

背景与实例见 [[decisions]]。

### 3.4 利益披露

**素材含推广内容时必须标注**（作者是产品运营者、带 UTM 链接等）：在 frontmatter 与摘要页写明，并把相关页面的 `confidence` 降级。

### 3.5 AI 生成内容

| 步骤 | 要求 |
|---|---|
| 收录 | **收**。理由是它作为「对照样本」有价值 —— 它示范了「结构完整度 ≠ 证据强度」 |
| 定级 | **按内容质量定，不按「是不是 AI 生成的」「AI 生成占多少比例」定** |
| 引用 | **可以被其他页面引用，但引用时必须标注其 AI 生成性质与 `confidence`** —— 不允许像引用一手材料那样直接引用 |
| 说明 | frontmatter 写明 `kind` 与收录理由；摘要页写明「低置信度的原因」与「仍然收录的原因」 |

**为什么不禁止引用**：完全禁止会让这类素材无法参与库内论证，而降级 + 标注保留了它作为反例的功能。

**注意区别于「推广内容」**：推广内容的问题是可追溯性（能追溯但动机有偏），AI 生成内容的问题是可追溯性为零，两者降级理由不同。

**判据的判据** —— 问一句：**「这段话如果错了，读者能不能自己发现？」**
- 能（有链接、有可试用的操作、有显式的「未验证」标注）→ 保留 `confidence`
- 不能（精确数字 + 模糊归属 + 无链接）→ 降级

**降级的是行为，不是作者身份。** 完整判据表与理由见 [[decisions]]。

### 3.6 证据问题分六类

**处理方式不同，不要混为一谈。**

| 类别 | 问题性质 | 处理方式 |
|---|---|---|
| 推广内容 | **可追溯，但动机有偏** | 标注利益披露 + 相关页降级 |
| 纯 AI 生成 | **可追溯性为零** | 按内容质量定级（见 3.5） |
| **伪引注** | **可追溯性被伪造** —— 精确数字配模糊归属，含年份/机构名，制造「有出处」的假象 | 整页降级 + **显式区分「不可追溯」（判断）与「已核实不存在」（事实）** |
| **弱引注** | **可追溯性被放弃** —— 精确数字配「有研究表明」，无年份/机构/期刊 | **逐条标「（未验证）」**，不整页降级 |
| **引注的使用失真** | **可追溯性完好，但数字/结论的对应关系被搞错** | **逐条公示「素材说 X ↔ 原文说 Y」**，不整页降级 |
| **过期引注**（**2026-09-19 单列**） | **引注真实、对应关系也对，但结论已被后来的研究推翻或大幅削弱** | **逐条标「（已过期）」+ 写明推翻它的研究；不得单独引用**，不整页降级 |

**前三类是「污染」，后三类不是。** 污染指来源本身出了问题，必须整页降级；弱引注是**强度不足** —— 它在科普写作里是常规做法，没有骗人，只是没把话说完整。**混同会让「引注不规范」看起来像「学术不端」**；反过来，把伪造当成不规范，则会放过更严重的问题。

**伪引注最危险**：前两类看署名就能警觉，伪引注要真去查才发现查不到。

**后三类的识别方法各不相同，而且第一步都不是「查有没有出处」**：

| 类 | 要查什么 |
|---|---|
| 引注的使用失真 | **这个数字在原文里指向什么** —— 核对**对应关系** |
| **过期引注** | **这个结论现在还成立吗** —— 核对**该研究的当前状态**（后续复现 / 元分析 / 作者撤回） |

### 3.6.1 「过期引注」的边界与判法（2026-09-19 单列时一并定下）

**它为什么不与前三类同列**：引注是真的、数字是真的、位置也对 —— **素材没有骗人**。
问题出在**时效**：那个结论已被后来的研究推翻或大幅削弱。
**时效本身不是素材的过错** —— 除非素材**明知结论已被推翻仍按既定事实陈述**，那是另一种问题（见下）。

**三条边界，不要混**：

| 容易混的类 | 区别 |
|---|---|
| **弱引注** | 弱引注是**没给出处**；过期引注是**出处给了、也是对的，只是过时了** |
| **引注的使用失真** | 使用失真是**数字安错了位置**；过期引注是**位置没错，结论本身失效了** |
| **伪引注** | 伪引注是**查不到**；过期引注是**查得到、而且真实** |

**一条升格判据（本库加）**：**若素材写于结论被推翻之后，却仍按既定事实陈述，则不算「过期」，而是「明知故用」** ——
它更接近**引注的使用失真**，甚至更重。
先例里的灰区：[[2026-09-18-extended-mind-notes]] 行 284 笼统提了一句「大样本重复失败」，
但**与行 230 的断言相隔 54 行、且互不引用**。**本库的判法：算「过期引注」** ——
理由是**分置而不互引，等于没有告知读者**。**这是一条可争议的判法，已记入 [[decisions]]。**

**连带影响 `confidence`**：若一页的**核心断言**依赖过期引注，该页 `confidence` 须降 ——
`evidence_tier` **管不了这件事**（它管来源类型，不管时效）。

**这类核查是持续性的，不是一次性动作。** [[2026-09-18-extended-mind-notes]] 收录当日得出的推论
（「库里所有引注都欠一轮『现在还成立吗』」）现在有了正式类别。库内已登记的候选（截至 2026-09-19）：

| 候选 | 位置 |
|---|---|
| 权力姿势的激素效应、面部表情反馈争议 | [[2026-09-18-extended-mind-notes]]（**本类首例**） |
| 蔡加尼克效应的普遍性 | [[2026-09-18-woop-notes]] |
| 安全型依恋比例 65–70%（当代元分析 51.6%） | [[2026-09-18-sense-of-security-notes]]、[[attachment-theory]] |
| 逆火效应 | [[2026-09-18-qa-admitting-mistakes-notes]] |
| 2013 年的学习技术评估本身 | [[2026-09-18-dunlosky-learning-techniques]] |
| 2008 年的反刍综述本身 | [[2026-09-18-nolen-hoeksema-rethinking-rumination]] |

> 数字散落在各页时，不改就会长期误导读者。

### 3.7 混层素材必须逐行比对数字

一份素材内部常混层（逐字引文 / 讲稿 / AI 阐释 / AI 报告并存）。AI 生成的摘要段会「**补进**」原文没有的具体数字 —— **但不总是**：

- 有的做**加法**：摘要段补进原文没有的具体数字或术语（可核先例：[[2026-09-18-hidden-potential-notes]] 补进正文没有的数字与术语、[[2026-09-18-clear-thinking-notes]] 自造「位置定律 The Law of Position」）。
- 有的做**减法**：摘要段每个数字都能在讲稿里找到，但漏掉了讲稿的 5 个百分比。

**同一来源、同一形态的两份笔记，摘要段的行为可以完全相反。因此不能按形态一刀切判定，只能逐份逐行核对。**

> [!warning] 2026-09-19 更正：本节原举的「加法」先例是错的 —— 而它错的方式，本身就是一条规则缺口
> 原文写「摘要段补进『挑战比技能高 4%』，而成书正文只说『略超过』」—— **这条先例已被推翻**：
> 原书 L7792–L7815 **有 4% 的完整论述**，真相是那份中文素材（**只占原书约 8%** 的节选）**没节选到**。
> **本库当时把一次「减法」误判成了「加法」。**（见 [[2026-09-19-art-of-impossible-book-en]]）
>
> **成因是一条规则缺口**：**在素材内部检索，无法区分「素材里没有」与「原书里没有」。**
> 因此 ——
> **① 判「加法」需要一手对照**（原书 / 原文 / 原始研究）。只有素材内部比对时，**只能说「该数字未在正文段出现」，不能说「它是 AI 补的」。**
> **② 一手文献的对照，同时还校准了本库自己的结论** —— 本条更正推翻的不是素材，是本库写在这里的规则示例。
> **③ 反过来也成立**：确认了「减法」的先例（[[2026-09-18-hyperefficient-notes]]）**不受影响**，因为它比的是同一份素材内部的段与段。

核对时必须比对「**摘要段**」与「**正文段**」的数字，不能只读摘要 —— **加法式缺陷比整段编造更难察觉：它只加一个数字，读起来更可信。**

**另注意区分三种缺陷，不要合并**：
- **「书里没有」**（素材编造）
- **「书里有但无引注」**（证据强度不足）
- **「书里有，但素材没节选到」**（**2026-09-19 新增** —— 这是**节选的完整性**问题，不是素材的缺陷，也不是证据强度问题。判这一条**必须有一手全文**，否则会像本库那样把它误判成第一类）

单一 `confidence` 不够，`sources/` 页要加**分层表**（段 / 行区间 / 性质 / 署名 / 置信度）。本库已有五层混层的先例（见 [[2026-09-18-learning-is-forgetting]]）。

### 3.8 核查分两级：L0 事实核查 / L1 全文校准（2026-09-19 北洛裁定）

2026-09-19 曾裁定「一手校准**制度化**」。同日北洛质疑其过重，经核查后**改为分级触发**。**本条取代「每份素材必经一手校准」的旧做法。**

**为什么分级，而不是整体降级**：实测 `raw/assets/` 里 10 份一手 PDF 有 9 份已提取入库，7 次校准**没有一次的成本发生在「找原文」环节** —— 瓶颈是「逐条核」，而它是可伸缩的。真正该区分的不是「做不做」，是**核查目的**：

| 核查目的 | 级别 | 需要什么 | AI 核片段够不够 | 收原文？ |
|---|---|---|---|---|
| **A. 这句话是不是真的**（数字 / 署名 / 引文） | **L0 事实核查** | 该断言出现的那一段 | **够** | **不必收** |
| **B. 这份素材少了什么 / 有没有把话说圆** | **L1 全文校准** | 一手**全文** | **不够** | 必须收 |

> [!note] B 为什么不能用片段做
> 依据是 §3.7 那条硬规则：**在素材内部检索，无法区分「素材里没有」与「原书里没有」。**
> 因此片段核查**只能证真、不能证伪**，还会把「遗漏」误判成「编造」—— 本库在「4% 原则」上犯过这个错。
> 更进一步：[[source-pool-bias]] 第 ③ 类遗漏（**问题供给枯竭**）本质是**没有人提出问题**，片段核查**无从知道该核哪一句**。

**L0（每次收录都做）**：对**带数字、带引号、带署名**的断言逐条核出处。
- 核的是「**这个片段里有没有这个断言**」，不是「**链接能不能打开**」—— 后者正是 §3.6「伪引注」最常伪装的形式。
- 核不到就如实写「未找到」或（未验证）。**「核过而没有」本身就是信息。**

**L1（命中任一触发条件才做）**：

| # | 触发条件 | 为什么 |
|---|---|---|
| 1 | **原文已在库**（`assets/` 有对应 PDF） | 零获取成本 |
| 2 | **该素材 / 该页的断言被下游引用 ≥3 处** | 传播面大，错了要回填多处 |
| 3 | **已出现具体怀疑**（数字对不上 / 引号内查不到 / 署名含糊） | 已有误差信号 |

- **都不命中 → 只做 L0**，并在该页正文写一句「本页未做全文校准」。
  ⚠️ **这句不设 frontmatter 固定字段**（北洛 2026-09-19 裁定）—— 它是正文里的一句话，不是可计算字段，加了会让 `lint` 与 `seed_evidence_tier.py` 误以为它参与证据计算。
- **不要攒到项目 `shipped` 前一次性清算**：一手校准**不是缺口驱动的**（填不上任何缺口表条目），而 `shipped` 的定义是缺口表清空，两者不同型；且 7 次校准**每次都要回填 5–8 处**，越晚做回填面越大 —— **攒着做是把成本从线性变成爆发**。

**L1 的三个专查动作**（本库已犯过的错都在这三类里）：**核数字**（含**数字的适用范围** —— 凡「A 与 B 都……」式并列断言，必须分别核 A、B 各自的数字）／**术语表核对 + 同形异义检查**／**核归属**（凡出现「某人 / 某公司提出了 X」，都要问「署名核过没有」）。

## 4. 查询

1. 先读 `wiki/index.md` 定位候选页（中等规模下比向量检索更可靠）。
2. 规模变大后用 `python3 tools/wiki.py search "<关键词>"` 做 BM25 检索。
3. 读相关页，**带引用地**综合作答。引用格式：`（见 [[page-slug]]）`。
4. **好答案必须归档。** 如果回答包含对比、综合、新连接 —— 写入 `wiki/analyses/<slug>.md`，并回填索引与日志。这样探索也会像素材一样复利。
5. 若发现知识缺口，在回答末尾列出「建议补充的素材 / 建议深挖的问题」。

### 4.1 「库里没有 X」是有检索记录的断言

**说「库里没有 X」之前，必须先在库内检索一遍 —— 而且检索了哪些段落必须说清。**

「库里没有」是一个**很强的断言**，比「我找到了」更容易说错，因为**没有任何东西会提醒你漏了什么**。

本库曾在一天之内因此错了**三次**，且三次成因完全相同 —— **只检索了混层素材的摘要段与讲稿段，漏掉成书正文第四部分**。

**操作要求：**

- 说「某素材没有 X」时，必须写明**检索了哪几段**（按分层表的段号 / 行区间）。只说「检索过」不成立。
- 素材是**混层的**，段与段的性质不同。在**一段**里没找到，不等于在**素材**里没有。
- 引用行号前**回原文核对一次**，不要凭记忆沿用 —— 错误的行号会被下游页面继承，且越传越难发现。

> [!warning] 这不是「谨慎」的问题，是「断言强度」的问题
> 「**不可追溯**」与「**不存在**」是两种强度的断言（见 3.6）。
> 「库里没有」属于后者 —— **说出口前必须有检索记录**。
> 反过来也一样：若检索后确实没有，**不要为了显得完整而含糊其辞**，直接写「没有」并注明检索范围。

## 5. 体检

人类说「检查一下知识库」时执行。跑 `python3 tools/wiki.py lint` 拿机器可查的部分，再人工/LLM 补下面这些语义问题：

- **矛盾**：两页对同一事实给出不同说法 → 用 `> [!warning] 矛盾` 块标出，并列双方证据。
- **过期**：新素材已推翻旧结论 → 旧页标 `status: stale`，并链接到新页。
- **孤岛**：无入链的页面。
- **该建未建**：被反复提及但没有独立页的概念。
- **数据缺口**：可以靠一次网络搜索补上的空白。
- **建议**：下一批值得找的素材、值得问的问题。

**项目层** —— 机器可查的部分工具链已覆盖，语义部分靠人：

| 检查项 | 谁查 |
|---|---|
| 项目页缺 `goal`、`stage` 取值非法、未链接任何知识页 | 工具链报错 |
| **已 `shipped` 但「当前缺口」表未清空**（「假 shipped」） | 工具链报错 |
| **「当前缺口」表已清空但项目还开着** | 工具链提示 |
| **未被任何项目引用的知识页** | 工具链提示，逐个人工判断 |
| **长期无产出的项目** —— 「产出」一节为空且 `stage: active` | 人工：要么降级，要么承认它是收藏而非项目 |
| **缺口过期的项目** —— 表里的条目是否还成立？已解决的有没有划掉？ | 人工 |
| **没做优先级排序的项目** —— `active` 项目若一条【阻塞】都没标，未必是没有阻塞项，更可能是**从没做过优先级判断** | 人工：逐条问「这一条真的不挡 `goal` 的验收吗」 |

**机器可查的语义提示** —— `lint` 会打印，但**不计入问题数**（它们不是「错了」，是「值得看一眼」）：

| 提示 | 判据 | 该怎么读 |
|---|---|---|
| **正文链接密度 < 1.5 条/千字**（2026-09-19 引入） | 正文内链去重数 ÷（正文字数 / 1000）；正文 <1,000 字的页、meta 页不参与 | 长文却几乎不在正文里引用别的页 = **清单式挂靠**（只写进 `related` 字段）—— 页面进了知识网，但没参与论证 |
| **名义交叉，实质同源** | ≥2 份支撑素材但全部来自同一来源族 | `evidence_tier: crossed` 在这里不成立，不能当独立佐证 |
| **未被任何项目引用的知识页** | 没有项目页链到它 | 按「项目是过滤器」的约定，要么挂进某个项目，要么考虑是否还值得维护 |

**密度阈值 1.5 不是理论值，是 2026-09-19 实测标定的**：素材页的密度中位数从 09-18 批次的 1.68 掉到 09-19 批次的 1.08（低于 1.5 的占比 40% → 83%），说明批量派生页时确实发生过一次退化，1.5 落在两批之间 —— 它是「能区分已知退化批次」的经验值，不要随手调。

> [!warning] 链接总数查不出这种退化
> `related` 字段与正文内链在 `lint` 口径里是**合并计数**的。一页哪怕正文里一句没提别的页，只要 `related` 写满，链接总数照样涨。
> 所以「页面数 / 链接数」这对数字**只衡量库有多大，不衡量知识有多结实**。要看结实程度，盯 **`single` 页占比**与**同源 crossed 数**。

每次 lint 完写一条日志：`python3 tools/wiki.py log lint "本轮发现 N 个问题"`。

## 6. 命名与写作

- 文件名：全小写，单词用 `-` 连接，英文 slug（`rag-vs-wiki`）。标题用中文写在 `title` 字段里。
- 素材文件名：`YYYY-MM-DD-slug.md`，日期是**收录日**（本项目约定，不用发布日）。
- **重新抓取同一素材**时，新文件加 `-r2` / `-r3` 后缀（`raw/2026-09-18-slug-r2.md`），**不修改旧文件**。新文件的 frontmatter 用 `supersedes` 指向旧版，用 `capture_note` 说明差异。差异必须同时记入对应的 `sources/` 摘要页。
- 语气：直接、信息密度高。不要「值得注意的是」「综上所述」这类填充词。
- 长度：概念页 60-200 行。超过 300 行说明该拆页。
- 数字与事实必须能追溯到 `sources`。**没有来源的断言要显式标注**：`（未验证）`。
- **`sources` 字段必须指向真正包含该内容的素材。** 如果一页的结论来自某处，而那里没有被收录进 `raw/`，就必须先补录素材，或把 `sources` 留空并显式标注缺口 —— **不允许指向一份并不包含该内容的素材**（悬空引用）。
- **二手来源与一手来源冲突时，以一手为准，并记录纠正过程。** 检索到的二手引用常有年份/数字误差（如把 1998 年的演讲记成 1999 年）。拿到原文后若发现不一致，**不要静默采用**，在对应 `sources/` 页与实体页写明「二手来源如此，原文为彼」。这类纠正是知识库的价值之一，不是瑕疵。
- **综合页（`analyses/`）必须逐节点标注证据性质。** 当一页把多份素材串成一条叙述时，**节点之间是「事实」还是「本库的推断」要分开说**。做法：列出每份素材覆盖的区间与其性质（一手/二手/通俗），并单独说明哪些结论属综合判断。默认 `confidence: medium`，除非每个节点都有独立一手来源。
- **单来源的实体页要显式声明。** 若一个实体页的全部内容只来自一份素材（尤其是二手或通俗文献），在页尾用 `> [!note]` 说明，并降 `confidence`。数字类断言（数量、年份、规模）若无一级来源，标注「（未验证）」。
  > 这条自 2026-09-19 起有机器兜底：这类页面的 `evidence_tier` 会自动是 `single`，并由 `seed_evidence_tier.py` 在正文顶部插入「孤证」警示块。
  > **机器只标「有几份来源」，标不了「这几份来源是什么性质」** —— 后半句（二手 / 通俗 / 未验证）仍须人工写，两者不重复。

## 7. 工具链

```bash
python3 tools/wiki.py <command>

  init [path]              在当前/指定目录初始化一个新的知识库
  lint                     健康检查：断链、孤岛、缺 frontmatter、重复 slug、项目层、证据层级
  stats                    统计：各类型页面数、链接数、孤立页、项目阶段分布、证据层级分布
  search "<query>"         BM25 全文检索（支持中文二字组）
  index                    从各页 frontmatter 重建 wiki/index.md
  build                    生成单文件浏览站点 site/index.html
  log <type> "<message>"   追加一条日志
  new <type> <slug>        按模板新建页面（type: project / source / entity / concept / analysis）
  graph                    打印链接关系（便于发现枢纽页与孤岛）
```

**零依赖**：只用 Python 标准库，不需要 pip install。

> [!note] 「页面总数」有两个口径
> `lint` / `build` **含** meta 页，`index` **不含**。判断 index 是否过期要**比 `wiki/` 文件数与 index 条目数**，不要比这两个数。
