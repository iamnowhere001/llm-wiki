# TraeCode 规则文档 — 规则体系的一手说明

> [[traecode]] 官方文档中「规则」一节的逐字副本。它是判断「AI 到底按什么规则干活」的**唯一权威依据** —— 因为它来自产品方，不是社区转述。

- **发表**：TRAE（字节跳动）
- **素材路径**：`raw/2026-09-18-trae-rules-docs.md`

## 关键要点

1. **规则分两类，作用域不同**：
   - **全局规则** —— 所有项目生效，存放于本地根目录 `~/.trae-cn/user_rules`（Windows 为 `%userprofile%/.trae-cn/user_rules`）。
   - **项目规则** —— 仅当前项目生效，存放于项目下的 `.trae/rules/` 目录。
2. **项目规则有四种「生效方式」**，系统会据此自动改写 frontmatter：

   | 生效方式 | 触发条件 | 自动设置的字段 |
   |---|---|---|
   | 始终生效 | 项目下所有对话 | `alwaysApply: true` |
   | 指定文件生效 | 对话中提及的文件匹配通配符时 | `alwaysApply: false` + `globs` |
   | 智能生效 | AI 依 `description` 判断相关性 | `alwaysApply: false` + `description` |
   | 手动触发生效 | 对话中用 `#Rule` 提及 | `alwaysApply: false` |

3. **`#Rule` 优先级最高** —— 文档明确写道：即使规则是「指定文件生效」或「智能生效」，只要在对话中用 `#Rule` 提及，AI 也会在本次对话中使用它。
4. **多层嵌套，上限 3 层** —— `.trae/rules/` 下可建子文件夹归类，系统递归读取，**至多支持 3 层**，第 4 层无法识别。这是官方明确给出的硬上限。
5. **子目录也能放规则** —— 支持项目中**任意子目录**下的 `.trae/rules/`，以及子目录里的 `AGENTS.md`。触发条件是「你在对话中提及该目录下的文件，或 AI 执行任务时读取了该目录下的文件」。这实现了**模块级规则的按需加载**。
6. **`AGENTS.md` 的定位与跨 IDE 可移植性** —— 文档原文：

   > AGENTS.md 是一个位于项目根目录的轻量级 Markdown 文件，用于向 AI 智能体提供行为指引。……在 TraeCode 中创建的 AGENTS.md 文件可以在**其他支持 AGENTS.md 的 IDE 中复用，反之亦然**。

   这是本节最值得记录的一句：它把 `AGENTS.md` 定义为一个**跨工具的约定**，而不是某个产品的私有格式。
7. **兼容 `CLAUDE.md` / `CLAUDE.local.md`** —— 从 Claude Code 导入项目时，这两个文件会被一并导入。
8. **默认不生效，需手动开启** —— 必须在 **设置 > 规则 > 导入设置** 处打开「将 AGENTS.md 包含在上下文中」和「将 CLAUDE.md 包含在上下文中」两个开关，智能体才会读取根目录的这些文件。**这一条极易踩坑**：文件放在那里不等于生效。
9. **可为 Git 提交信息单独设规则** —— 在规则文件中写 `scene: git_message` 字段即可；该字段与 `alwaysApply`/`description`/`globs` 兼容，**不受其他字段配置影响**，多个文件同时含该字段时规则叠加生效。
10. **最佳实践里有一条与「上下文新鲜度」直接相关**：

    > 新建或修改规则后，建议开启全新的对话再使用，以避免历史上下文与新规则产生冲突。

    以及：若项目中已有大量不符合规范的代码，模型可能沿用现有代码风格而非遵循新规则 —— 此时应明确声明当前任务是「重构」。

## 摘要

文档结构为：关于规则（应用场景 / 规则类型 / 规则所在目录）→ 创建全局规则 → 创建项目规则（操作步骤 / 多层嵌套 / 子目录规则）→ 在对话中引用规则 → 编辑删除规则 → 使用 AGENTS.md、CLAUDE.md 和 CLAUDE.local.md → 为提交内容设置规则 → 最佳实践 → 示例。

「应用场景」给出的三条理由分别是提升效率（一次配置长期生效）、统一标准（团队规范结构化）、保障质量（明确核心约束）。

「示例」一节按场景给出五组规则样例：基础交互（中文回答、关键逻辑加中文注释、超过 20 行考虑抽象）、通用编码、重构（小步重构 + 测试保障 + 代码审查）、代码可读性、性能优化。

## 与本库既有页面的关系

- **它把 [[three-layer-architecture]] 的第三层具体化了。** 本库把 schema 层放在 `AGENTS.md`，而这份文档说明了 `AGENTS.md` 在 IDE 侧是如何被加载和与 `.trae/rules/` 分工的 —— 也就是「schema 层」在真实工具里的落地形态。新建的 [[agents-md]] 页专门讨论这一点。
- **它是 [[llm-wiki-pattern]] 里「工具链尽量薄」取向的一个外部对照。** 本库选择零依赖 CLI，而 TraeCode 选择在 IDE 内做一套四档生效方式的规则系统 —— 两者解决的是同一个问题（让 AI 稳定遵守约定），路径不同。
- **与 [[second-brain-skill]] 形成有意思的三角**：一个是把 wiki 封装成 Skill，一个是把规则放进 IDE。三者的差异值得在文章里展开。

> [!warning] 本文档**没有**回答的问题
> 1. **AGENTS.md 的加载时机** —— 文档只写了「如何开启」，没写「何时读进上下文」「改了要不要重开会话」。这个问题只能靠社区实测（见 [[2026-09-18-trae-agents-md-vs-rules-forum]]）。
> 2. **AGENTS.md 与 `.trae/rules/` 冲突时谁优先** —— 文档没有给出优先级规则，只说 `#Rule` 引用方式优先级最高。
> 3. **`AGENTS.md` 是否受 3 层嵌套限制** —— 文档只在 `.trae/rules/` 的语境下提 3 层上限，子目录 `AGENTS.md` 的识别深度未说明。
