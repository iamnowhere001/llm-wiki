# 社区讨论 — AGENTS.md 与 rules 的区别，以及加载时机

## 关键要点

1. **社区对分工的概括（用户「汤圆」）**：`AGENTS.md` 是「轻量化、跨 IDE 通用的项目级总指引」，交代整体定位、角色身份、全局原则与流程，**偏宏观总纲**；`.trae/rules/` 是「多份细分规则文件」，侧重代码规范、架构约束、安全细则等**刚性执行条款**，支持全局/模块级、按条件触发或手动调用。二者互补。
2. **加载时机 —— 全帖的核心争议，也是官方文档的空白**：
   - 提问者问：是不是只在会话开始时加载、一个会话只加载一次？Trae Solo 里每个新任务是否都重新加载？
   - 用户「我勒个去」实测：**会话/任务启动时加载一次**，后续对话不重复读取；新建任务等于新会话，会重新加载。**但中途手动改了 `AGENTS.md`，当前会话不会感知，需开新任务才生效** —— 该用户自己标注「这点待验证，不确定最近版本有没有优化过」。
   - 用户「HancksLiu」认为取决于**缓存**：任务下第一次对话按设计注入全部，后续走缓存命中，命中与否「看 LLM 的能力」。
   - 用户「GeneralC」补充：每次提交提示词都会捎带，大概率命中缓存，**但换模型时缓存大概率全部失效**。
3. **一个关于「默认不存在」的细节** —— 提问者表示找不到这个文件，说明 `AGENTS.md` **不是产品自动生成的**，需要用户自己创建在项目根目录。这与官方文档「需手动开启开关」相呼应。

## 摘要

帖子是问答式的：提问者先问「二者区别」，得到社区解释后，紧接着追问「加载时机」。追问得到三种不完全一致的回答（缓存说 / 实测说 / 提示词捎带说），但**没有官方定论**。最后一层提问转向「文件在哪、怎么初始化」。

帖子的真实信息量在于：它证明了**「AGENTS.md 何时进入上下文」在社区层面仍是一个开放问题**。官方文档 [[2026-09-18-trae-rules-docs]] 的最佳实践里有一条间接印证 —— 「新建或修改规则后，建议开启全新的对话再使用，以避免历史上下文与新规则产生冲突」。这条官方建议与社区实测的「改后需开新任务」方向一致，但官方并未明确解释机制。

## 与现有知识库的关系

- **它补上了官方文档 [[2026-09-18-trae-rules-docs]] 留下的空白**，但用的是低置信度的方式 —— 本库因此把两条证据分开存放，而不是把社区说法写进官方文档的摘要页。
- **它对本库有直接的实践含义**：本库的 `AGENTS.md` 是 schema 层（见 [[three-layer-architecture]]）。如果「改后需开新会话才生效」成立，那么**修改 `AGENTS.md` 后应重开会话再继续工作** —— 这是一条可操作的运维约定，与 [[ingest-query-lint]] 的流程直接相关。
- **与 [[cybernetic-learning]] 有呼应**：规则的「生效方式」四档（始终 / 指定文件 / 智能 / 手动）本质上是**注意力过滤器**的分级 —— 什么常驻、什么按需唤起。这与本库把「项目缺口表」放在收录入口的做法是同一类设计。
