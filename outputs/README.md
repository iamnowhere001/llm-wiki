# outputs/ —— 外向产出

> 这一层放**给库外的人看的东西**。它**不是知识网的一部分** —— 不进 `wiki/`，
> 不被 `lint` 当知识页校验，也不出现在站点图谱里。

## 放什么

| 类型 | 例 |
|---|---|
| 对外文章草稿 | `llm-wiki-research` / `peak-performance` / `traecode-pkm-article` 三个项目的 `goal` 都是「写到能写出一篇对外文章的深度」 |
| 演示稿 | 从 wiki 页导出的 slides |
| 体检快照 | `lint` / `buildcheck` 的输出存档 —— 回答「站点还可不可信」要看历史快照 |
| 诊断文档 | 关于本库自身的一次性分析（如优化方案） |

## 不放什么

- **知识** → 那是 `wiki/`。判据：**它是不是「关于世界的一条断言」**？
  是 → `wiki/`；不是（是「我做了什么的产物」）→ 这里。
- **过程记录** → 那是 `wiki/log.md`。
- **原始素材** → 那是 `raw/`。

## 命名

`YYYY-MM-DD-短标题.md`。日期是**产出日**，与 `raw/` 用收录日同理。

## 与 wiki/ 的双向关系

产出常常**消耗** wiki 页（引用它们），也常常**回流** wiki 页（写文章时发现的新连接归档为 `analyses/`）。

`wiki/projects/<slug>.md` 的「产出」一节应当指向这里的文件 —— **否则项目页会一直在喊「产出缺口」，而没人知道产出在哪**。
