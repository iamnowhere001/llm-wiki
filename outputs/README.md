# outputs/ —— 外向产出

> 这一层放**给库外的人看的东西**。它**不是知识网的一部分** —— 不进 `wiki/`，
> 不被 `lint` 当知识页校验，也不出现在站点图谱里。

## 放什么

| 类型 | 例 |
|---|---|
| 对外文章草稿 | `llm-wiki-research` / `peak-performance` / `traecode-pkm-article` 三个项目的 `goal` 都是「写到能写出一篇对外文章的深度」 |
| 演示稿 | 从 wiki 页导出的 slides |
| 体检快照 | `lint` / `buildcheck` 的输出存档 —— 回答「站点还可不可信」要看历史快照。放子目录 `体检快照/` |
| 诊断文档 | 关于本库自身的一次性分析（如优化方案） |

## 不放什么

- **知识** → 那是 `wiki/`。判据：**它是不是「关于世界的一条断言」**？
  是 → `wiki/`；不是（是「我做了什么的产物」）→ 这里。
- **过程记录** → 那是 `wiki/log.md`。
- **原始素材** → 那是 `raw/`。

## 命名

`YYYY-MM-DD-短标题.md`。日期是**产出日**，与 `raw/` 用收录日同理。

## 提案状态表

> **每份提案都带 frontmatter `status`**（词表：`提案` / `已裁定` / `已执行` / `已废弃`），
> 外加两个计数 `open_executed`（未执行项数）/ `open_decided`（未裁定项数）。
> **状态写进 frontmatter，不写在正文散文里** —— 2026-09-29 之前它散在正文
> （如「partial（第 1-3 步已执行）」），机器读不出，于是台账停摆（见 [[decisions]] 未决事项总表 E 表）。
>
> **下表是渲染视图，不是事实来源。** 权威是 frontmatter，用一条命令汇总：

```bash
python3 tools/wiki.py proposals
```

| 提案 | 日期 | 状态 | 未执行 | 未裁定 |
|---|---|---|---|---|
| `2026-09-21-llm-wiki-优化方案.md` | 2026-09-21 | 已裁定 | 2 | 0 |
| `2026-09-21-第4步裁定请求.md` | 2026-09-21 | 已执行 | 0 | 0 |
| `2026-09-29-模板体检与优化方案.md` | 2026-09-29 | 提案 | 2 | 2 |
| `2026-09-29-知识库体验优化方案.md` | 2026-09-29 | 提案 | 9 | 4 |
| `2026-09-29-规范层与检查机制优化方案.md` | 2026-09-29 | 提案 | 2 | 1 |

> **体检快照不在本表里** —— 它们是周期性检查的产物，放 `outputs/体检快照/YYYY-MM-DD.md`（子目录）。
> `proposals` 只扫 `outputs/*.md`、**不递归**，故快照**不需要** `status` 字段，也不会被误当提案。
> 首份快照：`outputs/体检快照/2026-09-30.md`（P1-2 落地，2026-09-30）。

**词表的语义**（避免「部分执行」这类词无处安放）：

| 取值 | 含义 |
|---|---|
| `提案` | **还有未裁定项** —— 等着北洛拍板，所以它整体仍是「提案」 |
| `已裁定` | 裁定全部落定，但**还有未执行项** |
| `已执行` | 裁定 + 执行全部完成 |
| `已废弃` | 明确不再做 |

## 提案约定

1. **新提案必须登记** —— 加 frontmatter `status`，并在 [[decisions]] 未决事项总表的 **E 表**加一行。
   **没进 E 表的不算提出**（2026-09-29 定的：09-20 那次盘点只扫 `wiki/`、没扫 `outputs/`，正是台账停摆的直接原因）。
2. **裁定 / 执行后同步更新** `status` 与两个计数 —— 否则 `proposals` 报的还是旧状态。
3. **每次体检（`schema` §5）重跑 `python3 tools/wiki.py proposals`**，核对本表与 E 表。

## 与 wiki/ 的双向关系

产出常常**消耗** wiki 页（引用它们），也常常**回流** wiki 页（写文章时发现的新连接归档为 `analyses/`）。

`wiki/projects/<slug>.md` 的「产出」一节应当指向这里的文件 —— **否则项目页会一直在喊「产出缺口」，而没人知道产出在哪**。
